# 评论防滥用与概览修复

按用户要求由 Claude Code 只读调研提出方案，本次由 Codex 实施，完成后再由 Claude Code 审核。

- 评论、点赞、举报先进行静默输入检查、会话认证、封禁与额度检查，再按风险返回 428。客户端只在 428 后完成一次 Turnstile 并重试。身份创建、登录和 PIN 修改保留必需的验证。
- 一次有效验证授予当前私有会话 7 天信任期。软阈值（评论 3 次/小时、点赞 30 次/小时、举报 3 次/小时）重新挑战后有 1 小时风险宽限。硬额度和冷却保留，硬额度反复违规才计入 24 小时 strike，3/5/8 次分别临时限制 15 分钟/1 小时/24 小时。冷却中的重复点击不升级封禁。
- D1 原子条件写入保证多 Worker 实例下额度仍有效；前置只读检查减少无意义挑战。可信来源仅使用 Cloudflare 覆写的 CF-Connecting-IP，IPv6 按 /64 规范化。
- 评论保留 IP HMAC 与 AES-GCM 密文，公开接口显式列选择不包含网络信息。管理列表显示打码 IP 和作者 ID，完整 IP 通过按需接口读取并审计；后台可按评论来源封 IP、封用户 ID，查询及解除封禁。IP 密文/哈希 90 天清理；迁移前评论显示无来源。
- 详情标题统一使用番号，后台轮询不提前重写标题。概览“条记录”改为“刮削 N 次”，说明是同文件夹的任务历史；失败记录标为“刮削失败”。
