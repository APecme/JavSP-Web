## F1/F2 对比度方案与实施

仓库没有明确标为 F1/F2 的对比度报告。以下保留 Claude Code 对两个实证问题的候选归类；用户随后明确要求“按照 Claude Code 已提出对比度方案改”，现已实施推荐方案。下表的“当前”指修复前的色对。

`index.html` 按 `app.css` → `overrides.css` → `cinema.css` 加载样式；媒体库和详情的深色规则以最后一份为准。`login.html` 不加载 `cinema.css`。不能用已被覆盖的旧版浅色媒体库样式判断当前对比度。

普通小字采用 WCAG 2.x AA 的 4.5:1 门槛；下表根据相对亮度 `(L高 + 0.05) / (L低 + 0.05)` 计算，sRGB 分量在 0.04045 以下除以 12.92，否则按 `((c + 0.055) / 1.055)^2.4` 转换。

### 候选 F1：深色页面的低亮文字

`cinema.css` 的 `--lc-faint: #71717a` 用于分区计数、`.lc-facts dt`、详情文件字段名和缺图提示等小字。

| 背景 | 当前文字 #71717a | 建议文字 #8a8a93 |
| --- | --- | --- |
| `--lc-bg: #09090b` | 4.12:1 | 5.82:1 |
| `--lc-surface: #18181b` | 3.67:1 | 5.18:1 |
| `--lc-raised: #1f1f23` | 3.40:1 | 4.80:1 |

建议新增 `--lc-faint-text: #8a8a93`，只让上述文字选择器使用它，保留图标、悬停边框等仍用原变量的视觉层级。也可复用 `--lc-muted: #a1a1aa`，其在上述背景分别为 7.76／6.91／6.41:1，但次要文字会更亮。

详情 hero 叠有模糊图片、`brightness(.38)` 与透明渐变，实际背景不是固定 `--lc-surface`。纯色比值不能证明该区域通过。需用高亮、深色、缺失封面和隐私模式实测；如不足，优先加深文字区域遮罩或增加稳定底衬，再核算合成后的像素。

### 候选 F2：紫色按钮／选中标签上的白字

涉及 `cinema.css` 中 `[data-panel="overview"] .button.primary`、`.lc-tabs button.active` 和 `#task-detail-dialog .button.primary`。

| 状态／方案 | 前景／背景 | 对比度 |
| --- | --- | --- |
| 当前常态 | #ffffff／#b366d6 | 3.63:1 |
| 当前 hover | #ffffff／#c27ce2 | 2.89:1 |
| 推荐：保留紫底，改深色字 | #18181b／#b366d6 | 4.88:1 |
| 推荐方案 hover | #18181b／#c27ce2 | 6.14:1 |
| 备选：白字，单独加深按钮底色 | #ffffff／#8746a8 | 6.05:1 |
| 备选 hover | #ffffff／#9852ba | 4.94:1 |

优先采用深色字方案，仅改这三组规则的文字及相关图标，不改全局 `--lc-accent`。详情 primary 内的 `img` 当前通过 `filter: brightness(0) invert(1)` 强制变白，落地时须同步处理；`currentColor` 图标会随字色变化。选中标签的 `aria-selected="false"` 有单独的半透明规则，需保留其语义并单独核验，不能用过宽的 hover 规则覆盖。

白字深紫底备选需要独立按钮变量。不能只看字色：#8746a8 相对深色页面背景为 3.29:1，但相对 surface／raised 只有 2.93／2.72:1，按钮若需要边界来辨认控件，还须增加可辨认边框。此处纠正了仅与页面背景比较就认定按钮边界达标的局限。
