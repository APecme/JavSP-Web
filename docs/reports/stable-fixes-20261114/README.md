# 正式版问题修复与软链接支持

基线：v1.1.42（f031065）。本工作区未合入后续 main 功能。发布目标为 v1.1.43，实际发布状态以 GitHub Release 和工作流结果为准。

## 修复范围

- [#19](https://github.com/APecme/JavSP-Web/issues/19)：网页目录扫描与核心目录扫描共用忽略规则，遍历时剪枝，不进入被忽略目录；扫描根路径位于忽略目录内时也跳过。空规则列表不会误匹配所有目录。同步应用 skip_nfo_dir。显式提交单个文件或已选文件清单仍视为用户主动重刮，不套用目录扫描排除规则。
- [#20](https://github.com/APecme/JavSP-Web/issues/20)：相对输出模板含 {num} 时，识别当前目录是否符合模板结构及对应番号，重刮保留该目录。支持翻译标题变化、标题被截短及 ./ 前缀。绝对输出目录仍按显式设置执行。随片 NFO 本身不会被误认为已经整理。已有嵌套目录不自动迁移，已有覆盖策略仍然生效。
- [#21](https://github.com/APecme/JavSP-Web/issues/21)：OpenAI 翻译引擎使用中文指令，区分标题与简介；增加 temperature 配置，默认 0.1，支持 0–2。拒绝空值、非文本、截断、明显过长、重复行和大量省略号。标题命中异常校验时保留原文并记警告，不污染 NFO 和输出路径；接口故障继续报错。独立的 AI 翻译模式语义不变。检测属于启发式保护，不能判断所有语义幻觉；未连接报告者的 Sakura/Ollama 实例。
- [#17](https://github.com/APecme/JavSP-Web/issues/17)：预设“文件夹整理”增加“使用软链接整理文件”（summarizer.path.soft_link），与硬链接互斥，默认关闭。视频使用指向源文件绝对路径的符号链接，保留原视频；支持跨文件系统、多分 P、覆盖与失败回滚。撤销整理仅删除生成链接，不删除源视频。

## 软链接使用

开启“整理文件到输出目录”，将“使用硬链接整理文件”设为否、“使用软链接整理文件”设为是，然后设置输出目录。源视频不能随后移动或删除。

Docker 中链接目标使用容器可见的绝对路径；Jellyfin/Emby 等播放器容器必须将同一源目录挂载到相同路径。Windows 创建符号链接通常需要开发者模式或管理员权限，权限不足时明确失败，不自动改用移动或复制。
