# Web 流畅度优化实施记录

## 已实施

1. 页面与请求：手动任务默认 50 条，概览按页查询；搜索、日期、大小、状态筛选在数据库中完成。概览先按影片分组再分页，全局统计独立计算，自动刮削历史计数不受当前页面影响。输入去抖 200 ms，未变化的列表不重绘，保留详情图片与编辑内容。GET 请求共享、20 秒超时、失败退避，后台标签页暂停轮询，设置页不轮询任务。静态资源使用内容 hash 与 immutable 缓存。
2. 存储与图片：任务改为 SQLite WAL，摘要和原始日志分开，按 ID 更新/读取；列表不加载完整日志。图片路径按任务读取，概览使用最大 360×540 的 JPEG 缩略图，源文件变化后替换缓存。任务列表与图片支持 ETag / 304。
3. 后台资源：固定工作线程与全局并发上限，兼顾批次并发，异常也释放名额；目录批次只读取/校验一次配置，任务在一个事务中入库后开始执行。普通日志进度最多约每 0.5 秒合并持久化，图片路径事件和结束状态立即保存。启动恢复只读取中断任务，完成后释放活动日志缓存。下载器页面读取异步快照，最多 4 个刷新线程、5 秒缓存、每个配置单请求；自动清理保留在后台管理线程，不再由列表 GET 执行。
4. 验证与发布：新增分 P、数据库迁移/并发/分页、图片缓存、请求超时、版本判断、任务队列及下载器缓存回归；GitHub 的 bata 工作流先在候选 Docker 镜像内运行 Python 测试和 HTTPS 检查，再发布。

版本统一为 1.1.36，后端和前端都归一化重复的 v 前缀。正式 RELEASE_LABEL 为 v1.1.36 或 vv1.1.36 时，界面只显示 v1.1.36，并以 1.1.36 比较更新；bata 仍保留构建时间标签。本次只推送 main 触发 Docker bata，不创建正式版本标签。

## 本机复测

合成 5,000 条完成任务，每条 40 条事件。Python 3.12，Windows 本地磁盘，通常 3 次取中位数。完整原始结果见 [优化后基准](web-performance-after-2026-09-23.json)。

| 项目 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 保存一个任务 | 1,756.85 ms | 4.81 ms |
| 单任务详情 | 206.98 ms | 1.59 ms |
| 24 次封面路径查询合计 | 4,391.92 ms | 28.78 ms |
| 手动任务页面 API | 全量 231.26 ms | 50 条分页 34.95 ms |
| 手动页面解压后响应 | 约 5.46 MB | 56,394 B |
| 概览 24 条分组分页 | — | 102.14 ms |
| 手动分页未变化请求 | — | 33.36 ms，304 |

分页与原先全量接口的工作量不同，表格表示实际页面加载策略的变化。304 减少传输和重绘，仍需要数据库查询与摘要序列化；不是零成本的增量事件接口。原始 JSON 的 log_processing 项目刻意保留旧式逐条重扫微基准，不代表已经节流的 worker，也不用于宣称日志处理加速。

追加 [10,000 条历史复测](web-performance-10000-2026-09-23.json)：50 条分页中位数 76.45 ms，单任务保存 5.07 ms、详情 2.06 ms；概览分组分页 216.99 ms，仍有进一步优化空间。这些是少量本机样本，不是线上 p95 或 NAS 验收结果。

隔离浏览器使用 123 条合成记录验证：概览 6 页、手动任务 3 页、跨页搜索命中、详情编辑经历轮询仍保留输入、无空状态残留、重复 v 版本显示正常；检查时无浏览器控制台错误。真实网站爬虫响应、NAS 延迟、公网带宽、移动设备的 INP/LCP 不在该本机结果范围内。

## 升级、备份与回退

首次启动自动把 tasks.json 导入 data/tasks.db。非空旧记录先备份为 tasks.pre-sqlite.json；原 tasks.json 不修改。格式错误或重复任务 ID 会中止迁移，不会静默丢弃历史；迁移标记避免删除的任务重启后被再次导入。以后任务以 SQLite 为准。

数据目录应在本地持久化磁盘，影片路径可以仍在 NAS。WAL 需要可靠的本地文件锁；不要直接把 SQLite 数据目录放在不支持这些语义的网络共享。默认全局 4 个刮削进程，可设置 JAVSP_WEB_TASK_WORKERS（1～32），每批仍受预设并发限制。

升级前备份数据目录。备份正在运行的 SQLite 时应使用 SQLite backup API；如果直接复制文件，请先停止服务，避免遗漏 WAL。不要只把旧 tasks.json 当作升级后的实时备份。

需要回退旧 JSON 版本时，先停止服务，在新版源码目录使用 Python 3.12 导出：

```sh
python scripts/export_task_history.py data/tasks.db data/tasks.rollback.json
```

导出工具只读数据库，拒绝覆盖已存在的目标文件。核对任务数量并保留备份后，将导出文件作为旧版的 tasks.json，再启动旧版。导出包含原始日志、文件还原信息与所有任务字段。不要让两个不同版本同时写同一数据目录。

## 后续可测量的优化

大目录扫描目前仍是同步请求；本次批量配置与事务减少重复工作，未引入额外扫描作业接口。日志仍保存单任务有上限的日志尾部，并在合并保存时解析，未改为逐事件表。SSE、10 万级历史索引专项、前端重复旧函数清理、真实 NAS/移动设备指标可作为下一轮工作，不能由当前本机测试声称已完成。
