# 片库、自动监控与评论转发使用说明

本轮代码尚未部署。更新后请保留原 data 持久目录。

## 评论连接

浏览器访问本站 `/api/comments`，JavSP Web 服务器转发到 `JAVSP_COMMENTS_URL`，默认 `https://comments.rtioo.com`。主站用户须先登录；本站登录 Cookie 不会发送给独立评论服务。显式将环境变量设置为空可禁用评论服务。

`JAVSP_COMMENTS_VERIFY_URL` 可指定独立的人机验证服务，默认跟随评论上游。评论数据已同源转发，验证页面和 Cloudflare 验证组件仍需要浏览器访问；不能通过删除 hostname 或消息来源检查来绕过这一限制。

服务器需能访问评论上游。上游按 IP 的限流会按站点出口聚合，评论身份配额继续独立；当前不转发或伪造来源 IP，也不提供管理接口代理。

## 目录监控

管理员进入“自动刮削 → 目录监控 → 添加监控规则”，选择已挂载目录和刮削预设后保存。Docker 中填写容器能访问的目录。

- 默认每 30 秒检查一次，文件连续 60 秒未变化才进入现有刮削队列；慢速下载可增大稳定等待时间。
- 默认仅处理规则建立后新增或变化的影片。勾选“处理已有文件”可纳入原目录内容。
- 可以包含子目录、设置排除项、暂停/启用、立即扫描或删除规则。暂停只停止新提交，不终止已经创建的任务。
- 规则和文件观察记录保存在 data，重启后恢复。临时下载后缀、输出目录和 data 目录会排除；多段文件沿用现有分 P 识别。
- 目录离线或权限不足时会显示错误，并保留记录等待恢复。超大目录的首次建立和手动扫描可能较慢。

## 更新后的版本保留

应用更新保存在 `data/updates/apps`，当前选择保存在 `data/updates/app-current.json`。本轮修正基础镜像身份识别、更新中断状态、损坏副本重新下载和可用上一版本回退，并有真实进程重启测试。

不要删除 data 或更换未挂载旧 data 的容器。旧基础镜像的 PID 1 启动器无法由应用热更新替换，含旧启动器的部署需要手动更新一次 Docker 镜像后才能使用新启动逻辑。手动换镜像时，明确选择的新镜像仍优先；健康检查失败才按回滚规则恢复。

## 导航与页面

“概览”现在显示为“片库”，原有页面状态、搜索、分类与隐私设置保留。电脑左侧导航可展开/收起；手机保留左侧图标栏，点击菜单按钮展开左侧抽屉，点击菜单项、遮罩或按 Esc 关闭。

其他工作区已按片库视觉重新组织内容；详情标题栏按“编辑资料、关闭”排列，只有一个详情关闭按钮，剧照查看的关闭保持独立。

“热片”与“下片”本轮按要求**保持为空**，未实现任何页面、接口、配置项或数据。

- 热片：后续加入的片商网页爬取。
- 下片：从热片取得番号后，调用用户自行配置的下载脚本。

当前工作区没有任何相关代码：侧边栏仍只有原有 8 个视图（无占位菜单），后端没有对应路由，配置文件没有预留键，也没有调用外部脚本的执行路径。后续实现时再新增，不要提前在导航或配置中放占位项——`tests/test_navigation_client.cjs` 固定校验侧边栏按钮数量与视图清单，加占位项会直接失败。
