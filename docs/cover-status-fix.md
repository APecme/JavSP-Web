# 封面日志与列表状态不一致

## 原因与修复

刮削器生成文件名时先发送 JPG 输出路径；download_cover 随图片来源 URL 选用 PNG 等扩展名，随后更新 movie 的文件路径，但没有再次发送 output 事件。因此 Web 端保留旧路径，完成日志正常，文件计数却为零。

1. 路径确定后再次发送实际 output；海报生成成功后才发送封面完成事件，海报生成失败明确记录失败。
2. Web 端兼容历史扩展名：优先保留存在的明确路径，否则检查生成文件清单及同目录、同名的 JPG/JPEG/PNG/WebP 文件。支持自定义封面文件名，不递归搜索其他影片目录。
3. 服务启动时后台修复旧任务的 image_output 和缓存列表状态。读取挂载盘时不持有数据库事务；更新使用原记录比对，避免覆盖并发修改或恢复已经删除的任务。原始日志、元数据保持不变。
4. 不再仅因任务 succeeded 就把封面下载进度强行置为完成；实际文件缺失仍显示不可用。

## 验证与上线

完整 Python 回归 85 项通过，两组 Node 前端回归通过。新增验证覆盖实际封面/缩略图 HTTP 200、列表计数、历史缓存迁移、PNG/JPEG/WebP/大写扩展名、自定义文件名、无需移动视频时的正确事件、海报写入失败、缺失图片、慢挂载盘下继续轮询，以及并发删除不复活。

复现命令：

    python -m unittest discover -s tests -v
    node tests/test_web_client.cjs
    node tests/test_scan_client.cjs

本次测试使用 tmp/cover-tests-data 作为 JAVSP_WEB_DATA_DIR，并使用合成测试图片。

修复通过 main 分支的 bata 工作流发布。部署此版本并重启后，后台修复会验证文件并更新符合条件的历史记录，完成后普通列表轮询即可看到新状态。需保证图片挂载路径可访问；已经删除或未挂载的图片不会凭日志被标记为可用。发布后需在部署实例中检查图片显示。
