# 热片来源调研（第一阶段）

调研日期：**2026-10-30（UTC）**。覆盖用户给定的 **30 个地址**，另核查 **8 个从页面发现的相关入口**。

本轮对应“首先对每个网站进行大概了解”，交付来源目录、访问证据和页面建设建议，**不等于已经完成热片页面或接通排行榜**。现有“热片”占位、刮削、下载器及演示数据均未改动；没有定时抓取或下载任务。

## 1. 方法与结论边界

- 从开发环境匿名 HTTPS GET 获取有限大小的 HTML，核查页面标题、导航、榜单区标题、站点声明和重定向。不请求图片、视频、种子或播放地址。
- 未登录、未提交年龄确认、未解验证码，未尝试绕过地域限制或反爬；没有使用用户 Cookie、代理配置或密钥。
- 尝试 Studio 内置浏览器时提示没有授权的活动 Desktop 浏览器，需要启用远程控制。因此本报告是**静态 HTML 文本核查**，不是渲染后交互验收，JS 空壳只能标为待核。
- HTTP 200 不等于取得有效业务页；403 也不一定是验证码。地区提示、年龄确认、维护公告、JS 空壳、疑似域名停放分别记录。
- 未系统审查各站 robots.txt、使用条款、API/转载许可或商业接入资格。本报告的“候选”只表示值得下一步验证，**不是生产抓取许可或可用性承诺**。
- 未核查的定位必须标为“待核”或“仓库代码依据”，不以域名和历史印象冒充本次访问结果。`kin` 无法确认含义，仅研究用户所给 JAVLibrary 主域。

配套文件：

- [catalog.json](catalog.json)：30 站结构化来源目录；仅供设计，不由应用加载。
- [evidence-2026-10-30.json](evidence-2026-10-30.json)：38 条访问记录，包括时间、请求/最终地址、状态码及人工筛选的导航/声明片段。
- HTML 仅在本地临时目录检查，不纳入版本管理。证据只保留业务分类、榜单说明、错误提示；不保存商品标题、图片、广告链接、CSRF、Cookie 或鉴权信息。
- `html_utf8_sha256` 是本地解码成 UTF-8 的 HTML 检查副本摘要，并非原始传输字节摘要；`observed_fragments` 可能经过实体解码/标签剥离，不是连续原文摘录。

## 5. 热片页面建议（设计，尚未实施）

### 信息架构

建议把“热片”作为发现入口，但清楚分成三个视图：

1. **榜单/趋势**：来源、内容类型、原始榜单周期、更新/抓取时间；选择来源后保留其原始排序，默认不造“全站综合热度”。
2. **新作**：发行时间/收录时间分别标注，支持品牌/演员过滤；不拿发布时间假装热度。
3. **来源状态**：当前可用、需年龄确认、需登录、地区限制、验证码、维护、解析失效、缓存过期；展示最近成功时间和错误摘要，手动刷新不阻塞页面。

作品卡片复用片库样式，建议字段：来源原始名次、标题、番号/商品 ID、演员/创作者、片商/卖家、发行日、来源链接、榜单周期、已入库状态。未提供的评分/演员/日期留空，不能由猜测补齐。封面加载与现有隐私模糊保持一致；无封面也可浏览文字。

来源栏目分为：官方/平台榜、片商品牌榜、第三方趋势、资料补全。FC2、动画、游戏/同人、写真/创作者使用独立类型，不能把不同统计对象混成同一个榜。

### 数据模型与去重

后续实现可采用以下概念，**这里不是已经存在的 API/schema**：

- 来源：`source_id`、`source_group`、`service`、`category`、`source_url`、榜单种类与原始统计口径、授权/启用状态。
- 榜单快照：`source_id`、`board_id`、`subject_kind`（作品/演员/卖家）、`metric`、`window`、`source_updated_at`、`fetched_at`、`status`、`last_success_at`、解析器版本。
- 条目：`source_item_id`、`identifier_kind`、`identifier_raw`、`identifier_normalized`、`rank`、原始分数/评分尺度/人数（若有）、可选资料、来源详情链接、片库匹配。
- 普通作品以规范化番号匹配；FANZA CID、FC2 商品 ID、JVID 商品 ID、写真/动画 ID 保留各自命名空间。别名只是映射，不覆盖原始值；没有可信 ID 时保持来源内独立条目。
- DMM 与 FANZA 使用同来源族，按服务/分类区分榜单；任何未来综合评分必须防止对同源转载重复加权。不同站点/窗口的 1 位或 5 分不直接相加。
- 排名变化只能比较同来源、同榜、同窗口的连续成功快照；首次入榜、重新入榜、未在榜内与抓取失败不能混为一谈。

### 接入与安全边界

- 用户确认首批来源与获取权限后，先做**一个小范围、可维护的只读适配器**，不在页面打开时对 30 站并发请求。
- 使用服务端固定来源白名单、超时/体积上限、限频、缓存、单飞刷新和指数退避；禁止浏览器传任意 URL 触发服务端抓取。重定向每跳、DNS/IP、端口都需校验，避免 SSRF。
- 初步可考虑刷新 30–60 分钟、手动刷新冷却及按来源限并发；这是待验证的设计值，不覆盖站点要求，也不表示越频抓取获准。
- 读取失败保留最后成功快照并醒目标为缓存/过期；无缓存时真实空态；禁止用随机样例、广告、停放页或验证页覆盖成功数据。
- 远程文本用安全文本节点呈现，不执行远程 HTML/JS；链接仅允许可信 HTTP(S)，外链开启隔离；封面代理/缓存应复用安全机制并验证授权，不能直接无限代理任意资源。
- 不自动通过年龄确认/验证码、不规避地域/付费限制、不记录鉴权 Cookie；如确需用户会话，另行设计显式授权与凭据保护，不把敏感信息写进调研目录。
- 本页先只做资料发现、原站跳转与已有片库匹配。下载脚本、播放、磁力/种子或自动下片不在第一阶段范围内；后续需独立确认动作和权限。

## 6. 推荐实施顺序及待确认项

**首轮原型优先验证**：FC2 商品周榜 + FD2 作品周趋势 + FALENO/DAHLIA 品牌榜/新作。理由是已经看见有效业务页与明确栏目；仍需完成条款/授权、周期参数、字段及分页验证。品牌榜周期不明时只标“站内排名”，不能冒充周榜。

**有条件加入**：DMM/FANZA、JavDB、JAVLibrary、XCITY、AV Entertainment。先解决合法访问条件，再确认榜单口径与字段，不能承诺本次已接通。

**辅助补全/二期**：AvBase、av-wiki、R18.dev 用于资料；FREE JAV BT、JAV321、Javrate 先核实算法、授权与稳定性。JVID、Getchu、Hanime1 等独立内容类型按需规划，不混入首批真人作品榜。

写运行时代码前，需要确认：

1. 首屏优先“作品榜单/趋势”还是“片商新作”？是否接受两者分栏、不混合热度？
2. 首批先用上述可核查的只读来源，还是必须从某几个指定站开始？
3. 是否需要 FC2、动画、游戏/同人和写真？默认建议按内容类型隔离。
